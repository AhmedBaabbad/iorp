**فحوص إضافية أجريتها الآن بطلبات حقيقية (مؤقتة، حُذفت):** معرّفات B في **معاملات الاستعلام** (`supplier_id`، `shipment_id`، `customer_id`، `open-for-receipt`) → قوائم فارغة؛ **PATCH** لأمر شراء A بمورد/مادة B → 404؛ **تقارير PDF/معاينة** لمستندات B عبر `/reports/{key}/preview` → 404؛ التوقيعات `/approvals/…` → 404. **لا تسريب.**

**فجوات تغطية ملموسة (ليست ثغرات مثبتة):**
1. **214 مسارًا بمعرّف** خارج المسح الآلي: المبيعات 65، الإنتاج 61، الجودة 52، الإدارة 30، التقارير 6 — لها اختبارات يدوية لكن **بلا حارس** يكشف المسارات الجديدة.
2. الحالات التي فحصتُها يدويًا أعلاه (الاستعلام، PATCH بالمراجع، تقارير الجسم) **ليست ضمن الاختبارات الدائمة**.
3. الحارس نفسه **ينجح فارغًا تحت T-ENV** — يجب أن يتحقق من حد أدنى لعدد المسارات.
4. لا اختبار للمهام الخلفية العابرة للمنظمات (البدء التلقائي للطلبات، التنظيف) من منظور العزل.

**لا يُدّعى عزل كامل** بناءً على عدد المسارات المختبرة.

## 5. مراجعة النسخ والاستعادة (المهمة 5)
| المعيار | `recovery_drill.py` (Codex) | `iorp_backup.py` (Claude — مراجعة ذاتية صريحة) |
|---|---|---|
| الغرض | تمرين آلية على بيانات اصطناعية | أداة نسخ تشغيلية |
| التشفير | لا (اصطناعي — موثّق) | Fernet (AES-128-CBC + HMAC) بأجزاء 16 MB |
| إدارة المفتاح | — | متغير بيئة فقط؛ **لا تدوير، لا خزنة** — يحتاج قرارًا تشغيليًا |
| الاتساق | pg_dump لقاعدة اصطناعية ساكنة | لقطة `REPEATABLE READ` مُصدَّرة مشتركة بين العدّ وpg_dump ✅؛ **لكن الملفات تُؤرشف بعد القاعدة لا في نفس اللحظة** — ملف قد يُضاف/يُحذف بينهما (توثيق Codex يوصي بنافذة صيانة — صحيح) |
| سلامة البيانات والملفات | بصمة SHA-256 قبل الاستعادة، `--single-transaction`، مقارنة استعلام | بصمات، عدد صفوف كل جدول، بصمة كل ملف، روابط سجل→ملف |
| الاحتفاظ | — | 7/4/12؛ **عيب:** `prune` لا يتحقق من سلامة أحدث نسخة قبل حذف القديمة |
| النسخ خارج الخادم | غير منفّذ | غير منفّذ (جاهزة للنقل كمجلد مشفّر فقط) |
| أمان الاستعادة | حاوية جديدة بلا شبكة ولا منافذ، تنظيف مقيد بالملصق ✅ | قاعدة جديدة باسم `iorp_restore_verify_*` فقط، ترفض القائمة والمصدر ✅؛ **لكنها تعمل على نفس خادم المصدر** (في الإنتاج: حمل وصلاحية CREATEDB على خادم الإنتاج) — الأفضل خادم استعادة منفصل |
| التوافق مع الترحيلات | لا يختبر سلسلة Alembic (موثّق) | يسجل رقم الترحيل ويقارنه؛ لا يختبر الاستعادة إلى نسخة تطبيق أحدث |
| ملاحظات عيوب | **التحقق يعتمد على `assert`** — مع `python -O` يُعلن PASS دون فحص | **نص صريح غير مشفر مؤقتًا:** النسخ يكتب الـdump صريحًا في مجلد الإخراج ثم يشفّره ويحذفه (دون مسح آمن)؛ والتحقق يفك التشفير إلى مجلد مؤقت للنظام |
| القيود | لا بيانات حقيقية، لا RPO/RTO إنتاجي | استعادة منظمة واحدة غير مدعومة؛ اكتشاف أعمدة الملفات بالاسم (قد يفوت عمودًا) |

**غير متحقق للإنتاج (يبقى موثقًا):** الجدولة، النسخة خارج الخادم، إدارة المفتاح، RPO/RTO الفعلي، الاستعادة بعد ترقية نسخة التطبيق، استعادة منظمة منفردة.
