## الاختبارات

التشغيل الأول المستهدف: `1 failed, 84 passed in 184.72s`. الاختباران القديمان نجحا. فشل الاختبار الجديد لمرجع الناقل لأن العقد الفعلي يرد 422 مع TRANSPORT_RECORD_UNAVAILABLE وليس 404. راجعت خدمة validate ثم جعلت الاختبار يثبت الرمز المحدد، وتطابق الرد مع UUID غير موجود، وعدم إنشاء السائق. لم أغير خدمة التطبيق ولم أقبل أي 422 عشوائي.

التشغيل الموحد النهائي: **200 passed in 315.73s (0:05:15)**، رمز خروج 0، دون اختبارات فاشلة أو متخطاة في هذه المجموعات التسع. الأمر من جذر المستودع:

```powershell
python backend/scripts/run_batch1_baseline.py
```

المخرجات الختامية:


التشغيل يعطل اتصال قاعدة التشغيل بعنوان loopback على منفذ غير مستخدم، والاختبارات تستخدم fixtures SQLite المؤقتة. هذا ليس تشغيلًا شاملًا لكل اختبارات المشروع ولا اختبار تزامن PostgreSQL.

## المخاطر والعوائق المتبقية

- لا نسخة إنتاجية مجدولة أو مشفرة خارج الجهاز مثبتة بهذه الجولة. تفعيل ذلك يحتاج إعدادات التشغيل واعتمادًا منفصلًا؛ لا أعلنه منجزًا.
- سلسلة migrations وبيانات الأعمال الواقعية وRPO/RTO الإنتاجية **NOT VERIFIED**.
- التغطية الجديدة توسع العزل لكنها لا تشمل كل مورد/إجراء/تقرير. شمول جميع المسارات واختبارات PostgreSQL والتزامن وregression التشغيلي الكامل **NOT IMPLEMENTED في هذه الدفعة**.
- MFA وإلغاء جلسات المنصة الفوري واتساق تدقيق المنصة وstep-up وCI وتحسينات النشر مؤجلة للدفعات المعتمدة لاحقًا؛ لم تُصلح ضمن Batch 1.
- فحص npm الحديث معلق: فشلت محاولة الشبكة، ورفضت المراجعة الآلية التصعيد لأنه يرسل أسماء وإصدارات الحزم إلى registry.npmjs.org. لا ترقية أو تعديل lockfile. أرقام التقرير السابق لا تعد نتيجة حالية.
- ظهرت ملفات backup/iorp_backup.py وtests/core/test_backup_tool.py متزامنة من خارج هذه الجولة؛ لم تُختبر هنا ولا تنسب إليها نتيجة التمرين.

## التراجع والقرار

كل تغييرات هذه الجولة اختبارات وأدوات ووثائق. لا حاجة لتراجع قاعدة بيانات. إزالة الملفات المضافة وإعادة مقاطع الاختبارات الثلاثة فقط تعيد حالة ما قبلها؛ يجب الحفاظ على التعديلات الأخرى الموجودة مسبقًا. **توقف التنفيذ عند Batch 1**. اعتماد Batch 2 قرار لاحق بعد مراجعة النتائج والقيود؛ لا تعتبر هذه الجولة موافقة على الإنتاج.
