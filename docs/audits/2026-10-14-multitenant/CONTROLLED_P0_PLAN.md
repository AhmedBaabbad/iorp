## ترتيب التنفيذ المعتمد

1. **Batch 1 — بيانات واختبارات:** أدوات تمرين نسخ/استعادة منفصلة، تحديث عقد الاختبارين، توسيع العزل، تشغيل خط أساس موحد. لا بيانات حقيقية ولا migration.
2. **Batch 2 — بعد اعتماد جديد:** إلغاء فوري للجلسات وسياسات عمر وخمول قابلة للضبط، تدقيق ذري لدورة المنظمة والحصة، اختبارات نجاح وفشل وتزامن مناسبة.
3. **Batch 3 — بعد اعتماد جديد:** MFA واسترداد مختبر، إعادة مصادقة للقرارات الحساسة، أدنى تعديلات صلاحيات لازمة. أي migration أو تغيير عقد عالي الأثر يراجع أولًا.
4. **Batch 4 — بعد اعتماد جديد:** حجب التوثيق حسب البيئة، ترويسات مناسبة، فحص وترقية آمنة للاعتماديات وCI. لا نشر تلقائي.

## التراجع وحدود الأثر

تغييرات Batch 1 اختبارات وأدوات ووثائق فقط. التراجع يكون بإزالة الملفات المضافة لهذه الدفعة وإعادة مقاطع الاختبار المعدلة فقط؛ لا تستخدم إعادة ضبط شاملة للمستودع لأنه يحتوي تغييرات سابقة كثيرة. لا تغييرات API أو dependencies أو migrations أو بيانات تشغيلية. حاويات التمرين جديدة بأسماء عشوائية وlabel محدد؛ تُحذف تلك الحاويات فقط بعد التنفيذ. الأدلة الاصطناعية تبقى في `.tmp/` المستثنى من Git.

## بوابة الانتقال

راجع `BATCH1_REPORT.md` ونتيجة الاستعادة ونتيجة الاختبارات قبل اعتماد Batch 2. نجاح المختارات لا يثبت جميع workflows ولا عزل كل مسار؛ يظل ذلك التزام اختبار مستمر. لا يغني التمرين الاصطناعي عن اعتماد آلية نسخ تشغيلية مشفرة خارج الخادم واستعادة نسخة واقعية بإذن منفصل.
